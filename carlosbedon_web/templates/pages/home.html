Dashboard

Django template for Render, with Supabase Postgres and Storage. The same steps are in the repository README.

  1. Portfolio app. PortfolioHomeView renders /portfolio/.
  2. External Postgres. DATABASE_URL wins over POSTGRES_*. Use the Supabase session pooler on IPv4, user postgres.<project-ref>, and sslmode=require. Encode a $ in the URL password as %24. Set POSTGRES_WAIT=false.
  3. Static files in the image. The production image runs collectstatic at build time so WhiteNoise has staticfiles.json. Gulp compiles project.min.css.
  4. Migrations on boot. The production start script migrates, collects static files again, then starts Gunicorn on PORT.
  5. Secrets stay out of git. .env.example has placeholders only. Real env files are gitignored and excluded from the Docker build.
  6. Pre-commit. The local container installs the hooks on startup. They cover cleanup, private keys, pyupgrade, django-upgrade, isort, black, flake8, and djLint. GitHub Actions runs them with --all-files.
  7. Supabase Storage. Uploads use S3Boto3Storage and AWS_S3_ENDPOINT_URL, with path-style addressing. CSS and JS stay on WhiteNoise.
  8. Template branding. The visible name is Dashboard. The portfolio page says Welcome.
